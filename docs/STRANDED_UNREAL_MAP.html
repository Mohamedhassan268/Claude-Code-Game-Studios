Stranded in Unreal Engine, from A to Z

Muammel, this is your handover. You'll build the 3D game in Unreal: our existing simulation and quantum mind, inside a game that plays like The Sims 4, with a free camera, people with needs, and a menu of actions.

Written 5 November 2026 by Mohamed, with Claude. The 6 November judging uses the existing notebook, slides and pygame window, so this game isn't needed for it. Times are rough estimates for one full-time person using AI tools. The Unreal steps come from Epic's documentation and general knowledge, and nobody has run them on this project yet.

Start here

  1. Check your PC against Phase 0. If it falls short, tell Mohamed before installing anything.

  4. Build Phases 1 to 5 in order. That's the first version worth showing people.

The scale problem, which you must design around

A Sims lot is a house and garden, with time moving in minutes. St Vincent's terrain is 270 by 397 cells of 90 m, so about 24 by 36 km, and a person there acts once every 2 hours, over 48 steps. A person drawn to scale would be invisible and could cross several kilometres in one step.

The answer is two zoom levels. World view shows the real terrain, hazards and everyone's real positions. Camp view zooms into a small dressed area around the selected person, with their shelter, fire and supplies, so that eating or building looks right. Camp view is decoration only and feeds nothing back to the simulation. The ship is much closer to Sims scale, with a 7 m deck grid and 10-minute steps.

The phases

Each phase ends with a check. Don't start the next phase until it passes. Blue makes the first playable version. Orange is everything after that.

0. Machine and project

1 day
  • PC: Epic recommends Windows 11, a quad-core 2.5 GHz or faster CPU, 32 GB of RAM, a DirectX 12 card with 8 GB or more of video memory, and Lumen needs an RTX 2000 series, RX 6000 or newer. Epic's page gives no disk figure, so leave plenty of room on an SSD.
  • Install: Epic Games Launcher, Unreal Engine 5.8, and Visual Studio 2026, set up using Epic's "Setting Up Visual Studio" page.
  • Python side: clone the team repo's game branch, make a .venv from requirements.txt and requirements-physics.txt, and link the artifacts folder into the checkout root.
  • Repo: make a new repo for the Unreal project from the Claude Code Game Studios template, because our fork's game branch is set up for Godot. Add Unreal's .gitignore and Git LFS for binary assets. Check your LFS allowance first, since Unreal projects get large. If it runs out, use Perforce.
  • Studio setup: run Claude Code from the repo's root, because hooks are skipped from a subfolder. Run /setup-engine unreal 5.8 and keep modes.rigor on minimal. On the template's own test, standard wrote 30 documents before the first line of code and didn't produce a better game. The tool won't create the Unreal project for you, so create a C++ project in the editor.

Done when: python -m stranded_physics.entities.build run stranded_physics/scenario_cards/generated_eruption.toml prints a result, and the empty Unreal project builds from Visual Studio and opens.

1. Load the replay

2 days, good for Codex
  • Add a C++ game instance subsystem, UStrandedReplaySubsystem, that reads the JSON file below with Unreal's Json module.
  • Decode arrays with FBase64::Decode, then FCompression::UncompressMemory with NAME_Zlib, then read little-endian floats.
  • Test against tests/fixtures/tiny_replay.json in the Godot fork. It was written with Python's zlib, and tests/unit/test_replay.gd holds the expected values, so you can copy those tests.
  • Add a Playback class: pause, three speeds, seek, and stopping at the end.

Done when: Unreal Automation Tests reproduce every value in test_replay.gd, including elevation between cells and hazard frames that hold until the next change.

2. World view

3 days
  • Heightmap: Unreal's Landscape imports 16-bit images at set sizes, listed in Epic's Landscape documentation, so ask Mohamed for an export at your chosen size. Height scale is about 100 × height range in metres ÷ 512.
  • Coordinates: Unreal uses centimetres. Use X = (x_m − x0_m) × 100, Y = (y0_m − y_m) × 100, Z = height_m × 100. That puts east at +X and south at +Y, which fits Unreal's left-handed axes. Check this first, because a mirrored island is an easy mistake to make.
  • Sea and light: Water plugin or a simple plane, and a sun driven by the replay's hour.
  • Camera: a pawn with a spring arm and Enhanced Input. WASD or middle mouse to pan, right mouse or Q and E to orbit, wheel to zoom. See src/world/camera_rig.gd for the Godot version.
  • Performance: test early on the slowest PC you must support. Mohamed's has a GTX 1050 with 4 GB, well below Epic's recommendation, and may not run this at all. Try turning off Lumen and Nanite, or the Lumen Lite option reported in 5.8.

Done when: St Vincent is recognisable and the right way round, the camera works by hand, and it holds 30 frames per second on the target PC.

3. People and playback

4 days, art is the slow part
  • Import a rigged character, and use IK Retargeter to apply one animation set.
  • Build an Animation Blueprint with a state for each action, plus injured and dead.
  • Move people along path_m, evenly through each step, snapped to the ground. Start with one step taking about 8 seconds at normal speed, then tune it by playing.
  • Scale people up with camera distance in World view so they stay visible.

Done when: one person's whole generated_eruption run plays with the right animation at each step, they never walk across the sea, and scrubbing back gives the same picture.

4. Hazards on the map

2 days

Turn tephra.deposit_load and pdc.active frames into transient textures, and blend them into the Landscape material as ash and glowing flow. Add a basic eruption column from eruption.column_height. See src/world/terrain.gdshader for the idea.

Done when: in a test frame, the drawn flow matches the replay's pdc.active, and a person dies only when their record says so.

5. Sims-style screen

3 days
  • With UMG and CommonUI: needs panel, mood marker, thought bubble with option bars, event messages, person switcher, timeline and end-of-run summary.
  • A permanent evidence banner showing provenance.evidence_label. See the science rules.

Done when: someone who hasn't seen the project can say what the selected person needs and why they chose their action, unaided. This is the first version worth showing people.

6. Live play and player control

3 days on your side

Mohamed adds stranded_game/serve.py, a WebSocket server on 127.0.0.1 with a token passed at launch. You connect with Unreal's WebSockets module through FWebSocketsModule and IWebSocket, and build the round menu, action queue and Free Will toggle. The simulation already lets the mind be swapped per person through decide_fn (runtime/simulation.py:111), so this needs no change to physics.

Done when: with no player input, a live run's actions equal the replay's. Queued actions run in order, and the run is marked as player-directed.

7. Full hazards and Camp view

6 days

Niagara for ash fall, flows, mudflows, lava, rain, wind and storm, positioned from the fields. Effects can look nice, but where a hazard is must come from the data. Then Camp view, as in the scale note.

Done when: every hazard in generated_eruption and generated_storm shows at the right place and time, and Camp view changes nothing in the run.

8. Build mode

4 days

A UMG screen for the existing scenario builder. It sends drafts over the bridge, which applies the rules in entities/draft.py and check.py. Don't copy those rules into C++. It must produce the same TOML scenario files.

Done when: a scenario built in Unreal also runs from the command line, and the bridge gives the same errors as the old builder.

9. The Titanic

7 days plus the ship model

A ship that lists and sinks using ship.water_mass and ship.submerged, boats and seats, sea, and night sky. Mohamed extends the exporter for ships and packed crowd data. For the 2,201 people, evaluate Mass Entity with instanced meshes and animation baked to textures, and give only the followed few full skeletons. This approach hasn't been tested.

Done when: the whole ship plays at 30 frames per second or more on the target PC, and on-screen counts match ship.summary().

10. Sound and music

2 days

About five instrumental tracks from ACE-Step: menu, calm, unease, eruption, aftermath. Faded with MetaSounds using eruption.phase and needs. Sound effects come from a CC0 library, because ACE-Step describes itself as a music generator and doesn't list sound effects. It needs Python 3.11 or 3.12 and about 10 GB of models. Check the licence of the model weights on Hugging Face before release, and don't prompt with named artists or The Sims.

Done when: each loop joins cleanly by ear, and the licence of each sound is listed in CREDITS.

11. Package and ship

4 days

A Windows build, made with RunUAT BuildCookRun, with Python bundled alongside it. Smoke test on a PC that has never had Python or Unreal on it. Unreal has no simple browser version: Pixel Streaming needs a server, so plan on a download.

Done when: a stranger can unzip it, play a scenario to the end, and see the evidence banner.

Rough total: Phases 0 to 5 are about three weeks, and everything about ten to twelve weeks for one person, less if you already know Unreal well. The biggest unknowns are art and your PC.

The two formats between Python and Unreal

Replay file, schema 1

This is the brief Codex is building to, and the checker tests it. Island scenarios only for now.

{
  "schema": 1,
  "scenario": {"id", "title", "place", "step_minutes", "steps", "seed", "t0_local_hour"},
  "provenance": {"commit", "pack_hash", "verdicts", "evidence_label", "player_directed": false},
  "grid": {"nx", "ny", "dx_m", "x0_m", "y0_m", "stride"},
  "terrain": {"elevation": ARRAY, "land": ARRAY},
  "sites": {"name": [[x_m, y_m]]},
  "series": {"field name": [one number per step]},
  "hazards": {"field name": {"changes": [step], "frames": [ARRAY]}},
  "people": [{"id", "name", "mind", "outcome", "cause", "steps": [{
      "t", "day", "hour", "minute", "path_m": [[x_m, y_m]], "needs": {}, "stress", "injured", "alive",
      "event", "action", "probs": {}, "reason", "phase"}]}]
}

ARRAY = {"dtype": "float32", "rows", "cols", "zlib_b64"}
        little-endian floats, row 0 at the north edge, zlib, then base64
  • Arrays are downsampled to 200 cells or fewer a side, which suits hazards but is too coarse for final terrain, so ask for a separate heightmap export in Phase 2.
  • A cell's centre is half a full cell in from the grid's corner. src/replay/replay_data.gd shows the sums.
  • A hazard frame stays in force until the next step listed in changes.
  • The tile position in the old timeline.json and the hazard lists in _hazard_at are too coarse or mostly empty, so don't use them.

Rules that protect the science

  • Don't change contracts.py, gates, pass marks or models to make the game better. CI on the team repo checks gates and generated files.
  • A player-directed run is marked player_directed and can never feed a gate, claim or result.
  • Runs with no player input must equal plain simulation runs. Keep that test forever.
  • Always show the evidence label. The current Titanic is the case that matters: with quantum minds, 3.4% are saved against the real 32.3%, and the classical mind's 33.9% has the wrong breakdown. The ship sinks at 201 minutes against the recorded 160. Those are honest current results, so show them rather than hiding or adjusting them.
  • Quantum minds currently take their most likely option every time, so identical people do identical things, and that will look robotic. A sampling option exists in mind/quantum_mind.py. Using it is Mohamed's decision, and any game result that uses it must say so.
  • In the team repo, avoid plan, risk, role and skill in Markdown file names, and lib/ folders, because its .gitignore hides them. Don't push to main unless agreed.
